[P216|Heading 1] Introdução
[P217|Normal] Fundamentação
[P218|Normal] Escolhi criar a Loja Online Kid to Kid Braga, porque notei que existia um problema que precisava de ser resolvido. A ideia começou na escola, com o meu projeto "EcoVogue" (no programa Junior Achievement), onde já trabalhava a reutilização de roupa. Agora, decidi transformar essa ideia num produto real e profissional.
[P220|Normal] O grande problema é que a loja Kid to Kid, em Braga, não tem um catálogo na internet. Hoje em dia, isso faz muita falta. Para os clientes — principalmente grávidas ou pais com bebés de colo — é muito cansativo ter de ir à loja de propósito só para ver se existe um carrinho ou uma peça de roupa específica. Muitas vezes, fazem a viagem e não encontram o que procuram.
[P222|Normal] A minha solução foi criar um site moderno para resolver isto. O objetivo é facilitar a vida aos pais, permitindo-lhes ver os artigos em casa, no telemóvel, antes de saírem. Ao mesmo tempo, o site ajuda a promover a economia circular, incentivando a compra de artigos em segunda mão.
[P224|Normal] Na parte técnica, usei as ferramentas mais modernas para garantir que o site é rápido e não encrava (funciona como uma Single Page Application):
[P226|Normal] Na parte visual (o que o cliente vê): Construí a estrutura com HTML e Tailwind CSS para o site ficar bonito e organizado. Usei TypeScript e React (com Vite) para que as páginas mudem instantaneamente quando se clica, sem esperar.
[P228|Normal] Na parte dos dados (os bastidores): Usei Node.js e Firebase. Estas tecnologias garantem que o sistema de login é seguro e, o mais importante, que o stock está sempre atualizado: se um produto for vendido, sai logo da lista.
[P230|Normal] Basicamente, juntei o útil ao agradável: usei a melhor tecnologia que aprendi para modernizar uma loja local e ajudar as famílias de Braga.
[P233|Normal] Objetivos
[P234|Normal] Objetivos Gerais:
[P235|Normal] Demonstrar na prática tudo o que aprendi sobre programação e design ao longo dos 3 anos na EPB.
[P236|Normal] Aprender a organizar e planear um projeto grande do início ao fim, cumprindo prazos.
[P237|Normal] Desenvolver capacidade para resolver erros de código sozinho e procurar soluções para problemas técnicos.
[P238|Normal] Criar um site útil que incentive a reutilização de roupa e ajude a evitar o desperdício (economia circular).
[P240|Normal] Objetivos Específicos:
[P241|Normal] Construir um site visualmente atrativo e responsivo (que funcione bem no telemóvel) utilizando React (com Vite) e Tailwind CSS.
[P242|Normal] Utilizar o Node.js e Firebase para criar contas de utilizador, fazer login seguro e guardar os dados dos produtos na "nuvem".
[P243|Normal] Criar um catálogo onde seja fácil filtrar roupa (por idade, género e marca) e um carrinho de compras funcional.
[P244|Normal] Integrar o sistema Stripe para simular pagamentos reais de forma segura.
[P245|Normal] Desenvolver uma área reservada onde a loja possa adicionar novos produtos e gerir o stock de roupa usada de forma simples.

[P256|Heading 1] Componente Teórica
[P257|Normal] Para desenvolver a "Loja Online Kid to Kid Braga", escolhi um conjunto de tecnologias modernas e muito utilizadas no mercado de trabalho. O meu objetivo foi criar um site rápido, seguro e fácil de usar, simulando um ambiente profissional de desenvolvimento.
[P258|Heading 2] [🖼️ IMAGE x1] Linguagens de Programação e Ferramentas
[P259|Heading 3] React
[P260|Normal] O React é a tecnologia principal do meu projeto. É uma biblioteca criada pelo Facebook que serve para construir interfaces. Escolhi o React porque me permite criar "peças" independentes (chamadas componentes), como o cabeçalho ou o cartão de produto, e reutilizá-las em várias páginas. Isso torna o site muito mais organizado e rápido, funcionando como uma aplicação única (Single Page Application).
[P261|Caption] [🖼️ IMAGE x2] 
[P263|Heading 3] [🖼️ IMAGE x1] Vite
[P264|Normal] Para pôr o projeto a funcionar no meu computador, usei o Vite. Antigamente usavam-se ferramentas mais lentas, mas o Vite é muito rápido. Ele permite-me fazer alterações no código e vê-las a aparecer no site quase instantaneamente, o que poupou muito tempo durante o desenvolvimento.
[P266|Normal] [🖼️ IMAGE x2] 
[P268|Heading 3] [🖼️ IMAGE x1] TypeScript
[P269|Normal] Todo o código do site foi escrito em TypeScript. É uma evolução do JavaScript que nos obriga a definir o "tipo" de dados (por exemplo, dizer que o preço tem de ser um número e não um texto). O uso do TypeScript foi essencial para evitar erros ("bugs") e garantir que o site não falha quando o utilizador está a navegar.
[P270|Normal] [🖼️ IMAGE x2] 
[P271|Normal] [🖼️ IMAGE x1] 
[P273|Heading 3] JavaScript
[P274|Normal] Embora tenha usado TypeScript, a base de tudo é o JavaScript. É a linguagem de programação da Web. É o JavaScript que dá "vida" ao site, permitindo coisas como adicionar produtos ao carrinho, abrir e fechar menus ou comunicar com a base de dados em tempo real.
[P275|Normal] [🖼️ IMAGE x2] 
[P276|Normal] [🖼️ IMAGE x1] 
[P278|Heading 3] HTML (HTML5)
[P279|Normal] O HTML é o esqueleto de qualquer página web. No meu projeto, o HTML define a estrutura do site (onde estão os títulos, as imagens e os botões). Como usei React, o HTML é gerado de forma dinâmica dentro do código JavaScript (formato JSX).
[P281|Normal] [🖼️ IMAGE x2] 
[P282|Normal] [🖼️ IMAGE x1] 
[P283|Heading 3] CSS (Tailwind CSS)
[P284|Normal] Para dar estilo ao site (cores, tamanhos, tipos de letra), usei o Tailwind CSS. Em vez de escrever ficheiros de estilo complicados à parte, o Tailwind permite-me desenhar o site diretamente no código, usando classes pré-definidas (como flex para alinhar ou text-blue para mudar a cor). Isto facilitou muito tornar o site responsivo, ou seja, adaptável a telemóveis.
[P285|Normal] [🖼️ IMAGE x2] 
[P289|Heading 3] Radix UI e shadcn/ui
[P290|Normal] Para construir uma interface bonita de forma mais rápida, usei o shadcn/ui. Ao contrário das bibliotecas comuns, ele instala o código dos componentes diretamente no projeto, permitindo personalização total. Estes componentes são construídos por cima do Radix UI, o que garante que elementos complexos como menus móveis e janelas pop-up são acessíveis para todos os utilizadores (incluindo navegação por teclado e leitores de ecrã).

[P293|Heading 3] React Router
[P294|Normal] O React Router foi a biblioteca utilizada para gerir a navegação do site. É ele que permite criar as várias rotas (como a página de catálogo /produtos ou a página do carrinho /carrinho) e alternar entre elas instantaneamente, sem que a página fique branca a carregar.

[P297|Heading 3] React Hook Form e Zod
[P298|Normal] Para garantir que os dados que os clientes inserem (como moradas ou dados de registo) estão corretos, utilizei o React Hook Form em conjunto com o Zod. Enquanto o React Hook Form gere os campos do formulário de forma rápida, o Zod cria regras estritas de validação em tempo real (por exemplo, avisando imediatamente se o email não for válido).

[P468|Heading 2] Análise da Base de Dados
[P469|Normal] Este capítulo apresenta uma análise detalhada da base de dados Firebase Firestore utilizada na Loja Online Kid to Kid Braga. Serão abordadas a estrutura das coleções, os tipos de dados, as relações entre documentos e as regras de segurança implementadas.
[P470|Heading 3] Firestore Database
[P471|Normal] O Cloud Firestore é a base de dados NoSQL document-oriented da Google, integrada na plataforma Firebase. Foi escolhida para este projeto devido às suas características de escalabilidade automática, sincronização em tempo real e modelo de preços baseado em utilização.
[P472|Heading 3] Visão Geral das Coleções
[P473|Normal] A base de dados Firestore foi desenhada de forma otimizada, dividindo a informação nas seguintes coleções principais:
[P474|Normal] products: Guarda todos os dados dos artigos, como nome, preço, descrição, imagens, stock e categoria.
[P475|Normal] users e addresses: A coleção users guarda o perfil do cliente (nome, email, avatar). Dentro de cada utilizador, existe uma sub-coleção addresses que permite ao cliente guardar múltiplas moradas de envio.
[P476|Normal] orders: Regista todas as encomendas feitas, associando o cliente, os produtos comprados, o estado da entrega e o ID do pagamento do Stripe.
[P477|Normal] categories: Estrutura que define as categorias da loja (ex: Menina, Menino, Calçado).
[P478|Normal] reviews e reviewVotes: Coleções responsáveis pelo sistema de avaliações (1 a 5 estrelas) e pelos votos de utilidade dados por outros utilizadores.
[P479|Normal] coupons: Guarda os códigos de desconto, com regras de segurança estritas, como valor mínimo da encomenda, limite de utilizações e datas de validade (validFrom e validUntil).
[P480|Normal] promos_log: Registo histórico de todas as campanhas de newsletter enviadas aos clientes.
[P481|Normal] reviewReports: Coleção para guardar as denúncias feitas pelos utilizadores a avaliações abusivas ou spam.
[P482|Normal] audit_logs e analytics: Coleções isoladas e dedicadas a guardar estatísticas puras de vendas e registos de segurança, separadas do resto para manter a base de dados principal muito rápida.
[P484|Heading 4] Características do Firestore
[P485|Normal] O Firestore oferece várias características que o tornam ideal para aplicações web modernas:
[P486|Normal] Modelo de dados flexível: Documentos JSON com suporte para tipos complexos e sub-coleções.
[P487|Normal] Queries poderosas: Filtragem, ordenação e paginação nativas.
[P488|Normal] Sincronização em tempo real: Atualizações instantâneas em todos os clientes.
[P489|Normal] Offline persistence: Dados disponíveis mesmo sem conexão à internet.
[P490|Normal] Segurança integrada: Firebase Security Rules rigorosas para controlo de acesso.
[P491|Heading 4] Estrutura de Dados
[P492|Normal] O Firestore organiza dados em coleções de documentos. Cada documento é um objeto JSON com campos e valores. A estrutura do projeto utiliza principalmente coleções planas, mas recorre a sub-coleções (como nas moradas dos utilizadores ou itens do carrinho) quando faz sentido isolar dados de forma hierárquica.

[P527|Heading 3] Relações entre Coleções
[P528|Normal] O Firestore é uma base de dados NoSQL que não suporta joins nativos. Portanto, as relações são geridas através de:
[P529|Normal] Referências por ID: A coleção orders contém um campo userId que referencia a coleção users.
[P530|Normal] Desnormalização de Dados: Para otimizar a leitura, cada encomenda copia os dados do utilizador e da morada no momento exato da compra. Isto evita joins futuros e garante que a fatura não se altera mesmo que o cliente mude de morada anos depois.
[P531|Heading 3] Firebase Security Rules
[P532|Normal] As Regras de Segurança do Firebase avaliam quem pode ler ou escrever na base de dados, garantindo proteção a nível do servidor. No projeto, foram implementadas funções auxiliares (como isAuthenticated(), isOwner() e isStaff()) para tornar as regras impenetráveis.
[P534|Heading 4] Regras de Administração e Staff
[P535|Normal] Apenas utilizadores com papéis de admin ou staff (validado via "custom claims" ou e-mails específicos) podem criar, editar ou apagar Produtos, Categorias ou Configurações.
[P536|Heading 4] Segurança do Perfil e Carrinho
[P537|Normal] Para as coleções users, carts e favorites, os documentos só podem ser lidos ou alterados se o uid da sessão ativa for estritamente igual ao ID do dono (isOwner).
[P538|Heading 4] Proteção do Processo de Encomenda (orders)
[P539|Normal] Por motivos de segurança financeira e para evitar manipulação de preços pelo lado do cliente (Frontend), a criação de encomendas tem a regra de escrita bloqueada (allow create: if false;). As encomendas só são efetivadas internamente através do Backend (Cloud Functions) que tem privilégios de Administrador. Os clientes apenas podem atualizar uma encomenda para a cancelar caso esta ainda esteja como "pendente".

[P542|Normal] products: Filtros combinados de category, gender, condition em relação ao price e data de criação (createdAt).
[P543|Normal] products: Filtro de stock, marca e estado de reserva (isReserved).
[P544|Normal] orders: Filtros de pesquisa por cliente (userId) em combinação com o estado da encomenda (status) ou data.
[P545|Normal] reviews: Ordenação das avaliações pela utilidade (helpful) ou pontuação (rating).

[P792|Normal] Estrutura da Base de Dados: Como o Firestore é uma base de dados NoSQL, tive de pensar de forma diferente do habitual. Tive de fazer vários testes para perceber como organizar as coleções de produtos e utilizadores sem que o site ficasse lento.
[P793|Normal] Gestão do Estado do Carrinho: Garantir que o carrinho estava sempre atualizado em todas as páginas foi um desafio. Resolvi isto usando a Context API do React ligada ao armazenamento local do navegador.
[P794|Normal] Integração com o Stripe: Configurar os pagamentos foi muito complexo, especialmente a parte de pôr o servidor a "escutar" os webhooks do Stripe para confirmar se o cliente já tinha pago. Tive de ler muita documentação para conseguir fazer isto de forma segura.
[P795|Normal] O Apoio da Inteligência Artificial (IA): Para ser totalmente transparente, e refletindo a realidade do mercado de trabalho atual, utilizei Inteligência Artificial (Google Gemini) como ferramenta de apoio ao longo do projeto. Por exemplo, a lógica complexa do carrinho de compras e algumas dúvidas de estruturação do código foram resolvidas com a ajuda da IA. Funcionei com a IA como se fosse um "professor particular" ou "copiloto": sempre que bloqueava num erro do React ou do Firebase, pedia ajuda para entender o problema e gerar a lógica correta. Esta abordagem não fez o trabalho por mim, mas ajudou-me imenso a acelerar a aprendizagem, a entender código avançado e a construir o projeto sozinho sem estagnar nas dificuldades.
[P796|Heading 3] Resultados Alcançados e Aprendizagens
[P797|Normal] Apesar das dificuldades, os resultados superaram as expectativas. A plataforma é rápida, o código está limpo, bem organizado e seguro. Aprendi imenso sobre desenvolvimento Full-Stack (juntar a parte visual com as bases de dados e servidores), e ganhei muita autonomia a resolver problemas técnicos difíceis sozinho.
[P798|Heading 3] Otimização Semântica, SEO e Acessibilidade (Uso do HeadingsMap)
[P799|Normal] O desenvolvimento do frontend da Kid to Kid Braga, foquei-me na criação de um código HTML estritamente semântico, utilizando a ferramenta HeadingsMap para auditar a estrutura do site.
[P800|Normal] Esta abordagem trouxe três benefícios principais:
[P801|Normal] SEO Otimizado: Garanti uma hierarquia correta de títulos (H1 a H3), facilitando a indexação do Google para termos como "Produtos" e "Categorias".
[P802|Normal] Acessibilidade (A11y): Assegurei uma navegação lógica para leitores de ecrã, eliminando saltos na hierarquia de títulos e tornando a loja mais inclusiva.
[P803|Normal] Soluções Inteligentes: Através da auditoria, detetei a falta de um H1 na Homepage. Resolvi-o injetando um título com a classe sr-only (Tailwind CSS), o que manteve o design visual intacto, mas garantiu uma pontuação perfeita em termos de semântica e SEO.
